# ТЗ: специальный раунд «Танцуй иначе» в «Танцевальном батле»

Дата: 19.11.2026. Статус: к реализации после аудита текущей механики.

## 1. Цель

Сохранить классические карточки «Танец», «Караоке» и «Батл», добавив отдельную необязательную карточку **«Танцуй иначе»**. Её отличие: капитаны сначала выбирают усложнение, затем все команды выступают под три музыкальных фрагмента, после чего капитаны голосуют за победителя.

Это не замена текущего формата и не отдельная игра. Новая карточка использует очередь, таблицу, очки батла, пульт, экран и телефоны текущей механики.

## 2. Границы первой версии

Входит:

- новый тип карточки `special`;
- три фиксированных усложнения: «Только руки», «Как роботы», «Замедление»;
- голосование капитанов за усложнение до выступления;
- три музыкальных фрагмента по 3–15 секунд каждый;
- синхронная смена музыки по серверному времени;
- пауза, продолжение и повтор ремикса;
- финальное голосование и очки как в обычном батле;
- конструктор, проверка заполнения, предпросмотр, возвраты «Назад»;
- разбор старых игр без изменения их логики.

Не входит:

- загрузка видео участников;
- голосование всех участников команды вместо капитанов;
- произвольный набор усложнений в конструкторе;
- автоматическая запись выступлений;
- обязательный специальный раунд в старых и новых играх;
- публикация на test/production без отдельной просьбы владельца.

## 3. Пользовательский сценарий

1. Капитан текущей команды или ведущий выбирает карточку «Танцуй иначе».
2. На экране появляются три усложнения. Капитаны голосуют с телефонов в течение `voteTime`.
3. Участники команд видят варианты и подсказывают капитану, но отдельного голоса не имеют — как в текущем батле.
4. Ведущий нажимает «Начать батл: …». Выбранное усложнение фиксируется в снимке состояния.
5. Все команды выступают. На экране видны усложнение, оставшееся время и три участка ремикса.
6. Музыка переключается автоматически по серверному времени. Ведущий может поставить паузу, продолжить или начать ремикс сначала.
7. Ведущий открывает финальное голосование. Капитаны голосуют за другую команду, за свою голосовать нельзя.
8. Победитель получает `battlePoints`. При ничьей победителя называет ведущий.
9. Далее — обычный результат и ход следующей команды.

## 4. Автомат состояния

Классическая карточка:

```text
pick → perform → vote → result → nextTurn
```

Специальная карточка:

```text
pick → modifier → perform → vote → result → nextTurn
```

Правила:

- `modifier` — только `stage=question`, ответы `{ modifier }`, новый шаг не создаётся при выборе карточки;
- `perform` — `stage=reveal`, ответы не принимаются;
- финальный `vote` создаёт следующий `step`, чтобы ответы об усложнении и о победителе не смешивались;
- окончание таймера само не меняет этап: ведущий подтверждает переход;
- повторное нажатие перехода не должно создавать очки повторно — защита остаётся у общего `expect` и идемпотентного `useHostRun`.

## 5. Голосование за усложнение

Ответ имеет вид `{ modifier: "hands" | "robot" | "slow" }`.

Учитываются только:

- ответы текущего `step`;
- команды из текущего `order`;
- значения из белого списка усложнений.

Подсчёт:

- один голос команды даёт один балл выбранному усложнению;
- голоса всех команд учитываются, включая команду, выбравшую карточку;
- побеждает вариант с большинством голосов;
- при равенстве побеждает вариант, который раньше находится в списке: `hands`, затем `robot`, затем `slow`;
- при отсутствии голосов используется `hands`;
- после начала выступления изменить усложнение нельзя, кроме возврата к выбору карточки через «Назад».

Такое правило ничьей детерминировано, одинаково на всех устройствах и не требует скрытого случайного выбора.

## 6. Модель данных

В `DanceKind` добавляется `special`.

В `DanceCard` добавляется:

```ts
remix: Clip[] // ровно 3 для special; [] для остальных типов
```

Каждый фрагмент использует существующий `Clip`: `trackId`, `start`, `length`, `fadeIn`, `fadeOut` и остальные совместимые поля. Для специальной карточки длина ограничена 3–15 секундами, по умолчанию — 8 секунд.

В `DanceResult` добавляются:

```ts
modifier: "hands" | "robot" | "slow" | null;
elapsed: number; // прошедшие секунды выступления до текущего запуска/паузы
```

В `Prev` сохраняется `modifier`, чтобы возврат к прошлому результату восстанавливал правильную подпись.

Старые записи без этих полей разбираются как `modifier=null`, `elapsed=0`, `remix=[]` для обычных карточек.

## 7. Музыка и время

Общая длительность выступления — сумма длин трёх фрагментов.

Для каждого экрана вычисляется:

```text
elapsed = result.elapsed + (paused ? 0 : (serverNow - state.startedAt) / 1000)
remaining = max(0, totalDuration - elapsed)
segment = первый участок, для которого elapsed < конец участка
offsetInsideSegment = elapsed - начало участка
```

Требования:

- при переходе границы `playKey` меняется на индекс участка и `replay`;
- экран, открытый посреди выступления, запускает текущий участок с вычисленного смещения;
- видео в специальной карточке не используется, чтобы не было двух одновременных звуковых дорожек;
- все три трека предзагружаются при выборе карточки;
- отсутствие одного трека не меняет тайминги следующих участков; экран продолжает показывать ход раунда;
- после окончания времени ведущий сам открывает голосование.

## 8. Пауза, продолжение и повтор

Пауза:

- накопленное время добавляется в `elapsed`;
- `startedAt` и `timeLimit` очищаются;
- общий аудиофрагмент ставится на паузу;
- таймер и смена участков останавливаются.

Продолжение:

- `startedAt=server`;
- `timeLimit=remaining`;
- `elapsed` сохраняется;
- музыка продолжается с текущего участка.

Повтор:

- `elapsed=0`, `paused=false`, `replay += 1`;
- `startedAt=server`, `timeLimit=totalDuration`;
- первый фрагмент начинается заново.

## 9. Финальные очки

Для `special` действуют правила `battle`:

- капитан не может голосовать за свою команду;
- голоса за команды вне `order`, ответы другого шага и неизвестные значения не учитываются;
- один явный лидер получает `battlePoints`;
- ничья не даёт очков до решения ведущего;
- повторное разрешение ничьей очки не добавляет;
- отсутствие голосов означает отсутствие очков.

## 10. «Назад»

- Из `modifier` — к выбору карточки с очисткой ответов шага и сбросом усложнения.
- Из специального `perform` — к выбору карточки с очисткой шага; усложнение выбирается заново.
- Из финального `vote` — к началу выступления, финальные ответы очищаются, ремикс запускается сначала.
- Из `result` — к финальному голосованию, начисленные очки снимаются; уже закрытое время не возвращается.
- Из следующего `pick` — к прошлому результату через `prev`; `modifier` восстанавливается.
- Повторные возвраты не должны удваивать снятие или начисление очков.

## 11. Конструктор и проверка

Новая кнопка «+ Танцуй иначе» добавляет карточку с тремя пустыми фрагментами по 8 секунд.

В карточке доступны:

- название и подсказка;
- стиль;
- три музыкальных `TrackTimeline`;
- пояснение фиксированных усложнений.

Видео и обычный одиночный трек у специальной карточки скрыты.

Ошибки запуска:

- отсутствует любой из трёх `trackId`;
- название отсутствует — подставляется «Танцуй иначе» в интерфейсе, но проверка треков обязательна;
- повреждённые значения `remix`, `modifier`, `elapsed` нормализуются парсером и не приводят к исключению.

## 12. Роли и представления

Экран:

- выбор усложнения и число ответов без раскрытия промежуточного распределения голосов;
- выбранное усложнение, команды, таймер и текущий фрагмент;
- финальное голосование и обычный результат.

Телефон капитана:

- выбор усложнения, подтверждение ответа;
- во время выступления — правило и текущий музыкальный стиль;
- финальное голосование за другую команду.

Телефон участника:

- просмотр вариантов и состояния;
- подсказка «Голосует капитан».

Пульт:

- переходы по этапам;
- счётчик ответов;
- пауза/продолжение/повтор;
- разрешение ничьей и возвраты.

Режим `screenMode=none` остаётся неподдерживаемым для всей механики, как прежде.

## 13. Совместимость и безопасность

- Старые карточки не меняют этапы, очки и медиа.
- Новые поля читаются только через белые списки и ограничители.
- Неизвестный `kind` по-прежнему становится `dance`.
- Неизвестный `modifier` становится `null`.
- `elapsed` не может быть отрицательным, бесконечным или превышать общую длительность при вычислениях.
- Ответы проверяются по текущему шагу и текущему порядку команд.
- Треки перечисляются `danceTrackIds` вместе с треками обычных карточек.

## 14. Аудит текущей реализации перед правками

Подтверждено кодом и тестами:

- выбор только текущей командой;
- средняя оценка без голоса выступающего;
- запрет голоса за себя в батле;
- разрешение ничьей ведущим;
- возвраты и снятие очков;
- безопасный разбор ссылок на видео.

Риски, которые новая логика обязана закрыть тестами:

1. Смешивание ответов об усложнении и о победителе на одном шаге.
2. Повторное начисление очков при двойном переходе.
3. Разные победители голосования на разных устройствах при ничьей.
4. Смена музыки по локальному таймеру без учёта серверного времени.
5. Продолжение отсчёта во время паузы.
6. Запуск ремикса с начала при повторном открытии экрана.
7. Потеря выбранного усложнения при возврате к предыдущему результату.
8. Появление специальной карточки в старых играх без трёх треков.
9. Одновременное проигрывание обычного трека и ремикса.
10. Слом автоматического предпросмотра из-за нового действия.

Замечание к существующему паспорту: `mediaIds` по контракту относится к изображениям, а не к музыкальным трекам. Поэтому подключать туда `danceTrackIds` нельзя. Для ремикса используется отдельный сбор идентификаторов и предзагрузка на экране.

## 15. Критерии приёмки

- Все прежние профильные тесты проходят без изменения ожидаемых классических правил.
- Новый полный сценарий проходит от выбора карточки до начисления очков.
- Ничья усложнения, ничья команд, пустые и чужие ответы проверены.
- Пауза, продолжение, повтор и открытие посреди выступления проверены по времени.
- Все возвраты проверены, включая снятие очков.
- Автоматический предпросмотр доходит до конца специальной карточки.
- Конструктор не даёт запустить специальную карточку без трёх треков.
- `npm test`, `npm run build` проходят.
- В Chromium проверены конструктор и представления трёх новых состояний; консоль без ошибок и 404.


## 16. Результат реализации и аудита

Реализовано в локальной рабочей копии, без коммита и выкладки:

- модель `special`, три фрагмента ремикса, конструктор и обязательная проверка треков;
- этап `modifier`, два раздельных голосования, очки и ничьи;
- экран, пульт и телефоны капитанов/участников;
- серверный таймер, пауза/продолжение/повтор, открытие экрана со смещением;
- возвраты и автопредпросмотр;
- памятка ведущего и паспорт логики.

Проверки:

- **13/13 профильных тестов** танцевальной механики;
- полный набор JoyRest и production-сборка проходят;
- настоящие компоненты в Chromium: конструктор, `modifier`, `perform`, `vote`, пульт и телефон — без ошибок и 404;
- визуальный дефект перекрытия индикатора выступления найден и исправлен;
- настоящие WAV подтвердили звуковое переключение `track1 → track2 → track3`;
- автопредпросмотр специальной карточки доходит до награждения.

Не проверялось: реальная сессия на test/production с PostgreSQL, два одновременных пульта и внешние видео — они не относятся к новой специальной карточке без видео. Эти проверки нужны отдельно перед публикацией.
