# Техническое задание: ролевая игра «Олимп»

**Версия:** 1.0 от 10.10.2026
**Автор идеи:** Михаил Полхов
**Где будет работать:** собственная игровая платформа автора (проект joyrest), арендованный облачный сервер

## 0. Как читать этот документ

- **[РЕШЕНО]** — решение автора, менять только с его согласия.
- **[ПРЕДЛОЖЕНИЕ]** — проработанный вариант, принятый за основу, но ещё не подтверждённый окончательно. Можно менять.
- **[ОТКРЫТО]** — вопрос, на который нужен ответ автора (список в разделе 17).

## 1. Концепция в двух абзацах

Командная ролевая игра в духе Dungeons & Dragons. Каждый игрок играет за **греческого бога**. Ведущий выбирает **историю** — сюжетное приключение в одном из миров многоуровневой вселенной (Олимп, королевства рас, 9 кругов Ада по Данте, Тёмный мир, Внеграничье, скрытые туманные миры). По ходу истории боги разговаривают с персонажами, сражаются с врагами, получают очки характеристик и артефакты.

Исход любого действия — разговора или боя — решает **анимированный кубик d100** на экране. Характеристики богов растут и падают по ходу игры, но враги растут вместе с группой, поэтому игра не становится лёгкой. Истории можно проходить цепочкой: любая история может продолжить любую другую, а всё случившееся записывается в общую «Сагу» группы.

## 2. Формат партии и роли

| Роль | Устройство | Что делает |
| --- | --- | --- |
| Ведущий | планшет или ноутбук — **пульт** | выбирает историю и сцены, видит карточки всех игроков, может добавлять и отнимать характеристики (с журналом), запускает ходы врагов |
| Игрок | свой телефон — **экран игрока** | видит свою карточку бога, артефакты, бросает кубик, распределяет полученные очки |
| Общий экран | ТВ или проектор | карта мира, бросок кубика крупно для всех, появление врагов и персонажей |

**Ход партии [РЕШЕНО]:**

1. Персонажей (богов) распределяют между игроками.
2. Ведущий выбирает историю из предложенных (игра предлагает 3 подходящие — см. раздел 12).
3. Группа проходит историю: встречи с врагами и дружественными персонажами, диалоги и бои на кубике.
4. В конце история записывает последствия в Сагу; можно сразу начать следующую.

**Масштаб на старте [РЕШЕНО]:** 2–3 одновременные партии, до 20 участников всего.

**Режим без ведущего [РЕШЕНО]:** заложить в формат историй сразу, реализовать позже.

## 3. Персонажи: 40 греческих богов

### 3.1. Требования [РЕШЕНО]

- 40 самых известных богов греческой мифологии.
- У каждого бога: уникальные свойства и характеристики, привязанные к его мифам и «достижениям».
- Боги сбалансированы: нет очевидных силачей.
- У каждого бога прописан лор, частично из мифов, связанный в общую вселенную.
- **Основные способности бога неизменны**, характеристики по ходу игры растут и падают.

### 3.2. Визуал карточки [РЕШЕНО]

- Портрет **человекоподобный, реалистичный, сочный** — не мультяшный.
- Карточка **анимирована**: медленный наезд камеры на портрет, эффекты по стихии бога (молнии у Зевса, угли и туман у Аида, солнечный свет у Афины), блик по карточке.
- **Эмблема** — герб из исторических символов бога (Зевс — орёл и молния, Аид — двузубец и кипарис, Афина — сова и олива).
- На карточке: имя, роль, символы, мир, характеристики, способность, слабость.
- Карточка есть у игрока на экране и у ведущего на пульте; меняется в реальном времени.

Макеты: см. ссылки в `README.md`. Шаблон карточки: `шаблоны/04_шаблон_бога.md`.

## 4. Характеристики

### 4.1. Шкала [РЕШЕНО]

- Характеристики измеряются **от 0 до 100**. Так прибавка в несколько очков ощущается, но не ломает баланс.
- Основные способности бога не меняются, характеристики растут и падают по ходу игры.

### 4.2. Набор характеристик [ПРЕДЛОЖЕНИЕ, финальный список — ОТКРЫТО]

| Характеристика | Что даёт |
| --- | --- |
| Мощь | сила атаки, урон |
| Мудрость | понимание, видение скрытого, защита от обмана |
| Хитрость | блеф, кража, обходные пути |
| Влияние | убеждение, помощь союзникам, переманивание |
| Стойкость | защита, сопротивление эффектам |
| Удача | случайные события, шанс найти лучшее |
| **Здоровье** | отдельная шкала 0–100 для боя [РЕШЕНО] |

### 4.3. Стартовые значения и пределы [ПРЕДЛОЖЕНИЕ]

- Сумма шести характеристик у каждого бога на старте — **300** (в среднем 50). Сильная сторона бога — 70–80, слабая — 20–30.
- В анкете игрок распределяет ещё **20 бонусных очков** (не выше 80 в одной характеристике на старте).
- **Потолок** итогового значения (с артефактами) — 95. Выше 70 каждое очко стоит дороже: 2 полученных очка дают +1.
- **Минимум** — 5: характеристика может падать, но не до нуля.

### 4.4. Анкета игрока [РЕШЕНО — анкета есть; поля — ПРЕДЛОЖЕНИЕ]

- Имя героя-аватара и выбранный бог.
- Распределение бонусных очков.
- Выбор 1 из 2 талантов этого бога.
- Цель персонажа в сюжете (власть на Олимпе, месть, спасение кого-то и т. п.).

## 5. Кубик

### 5.1. Решения [РЕШЕНО]

- Исход решает **визуальный кубик d100** с красивой анимацией по кнопке «Бросить кубик».
- Кубик используется и в **боях**, и в **диалогах**.
- Число выбирает **сервер** (честный генератор), бросок пишется в журнал. Устройство игрока только проигрывает анимацию.
- За врагов кубик бросает **сервер автоматически**, ведущий только запускает их ход.

### 5.2. Формула броска [ПРЕДЛОЖЕНИЕ]

Больше — лучше (так интуитивнее для игроков).

- **Порог** = 100 − характеристика + сложность сцены.
- Бросок ≥ порога — успех. Каждое очко характеристики = +1% к шансу.
- Сложность: 0 (обычно), +10 (трудно), +20 (очень трудно), −10 (легко).

| Бросок | Исход |
| --- | --- |
| 96–100 | **Критическая удача** — всегда, при любой характеристике |
| ≥ порог + 20 | Хорошо |
| ≥ порог | Средне (успех) |
| < порога | Плохо (провал) |
| 1–5 | **Критическая неудача** — всегда |

Пример: Хитрость 60, сложность 0 → порог 40. Нужно выбросить 40+, шанс успеха 61%.

### 5.3. Анимация [ПРЕДЛОЖЕНИЕ]

Стиль кубика зависит от мира: золотой на Олимпе, костяной в Аиде, ледяной на 9-м круге. Замедление перед остановкой, вспышка на критической удаче, трещина на критической неудаче. Бросок одновременно виден на телефоне игрока и на общем экране.

## 6. Диалоги

### 6.1. Решения [РЕШЕНО]

- Диалоги с персонажами построены на бросках кубика.
- У каждого диалога **минимум три поворота** в зависимости от броска (критическая удача, критическая неудача, другие значения).
- От броска зависит, **сколько очков характеристик** получит игрок. После разговора на экране: «Вы можете распределить N очков», игрок распределяет сам.
- Диалог может давать **артефакт**.
- **Кто участвует в диалоге — решает кубик**, но работает «мешок судьбы»: кто уже участвовал, выпадает реже; за историю каждый игрок гарантированно участвует хотя бы раз.

### 6.2. Награды за диалог [ПРЕДЛОЖЕНИЕ]

| Исход | Очки на распределение | Прочее |
| --- | --- | --- |
| Критическая удача | +5 | лучший вариант сюжета, шанс на артефакт со всеми плюсами |
| Хорошо | +3 | |
| Средне | +2 | |
| Плохо | +1 | персонаж охладевает (отношение −10) |
| Критическая неудача | 0, одна характеристика −2 | осложнение сюжета; диалог может перейти в бой |

**Норма наград на историю:** не больше 15–20 очков на игрока и 1–2 артефакта на группу (проверяется конструктором автоматически).

## 7. Бой

### 7.1. Решения [РЕШЕНО]

- **Здоровье** 0–100, отдельно от характеристик.
- При нуле здоровья бог не умирает, а **изгнан во Внеграничье** до конца сцены. Вернуть его могут союзники или специальный бросок. Изгнанный теряет ход и, возможно, один артефакт.
- Враги бросают автоматически (сервер).

### 7.2. Ход боя [ПРЕДЛОЖЕНИЕ]

1. Очерёдность: по броску Удачи; Эос всегда первая, Гефест последний.
2. Атака: бросок по Мощи (или по характеристике способности) против Стойкости цели (как сложность).
3. Урон при успехе: 10 + (Мощь − 50) / 5; при «хорошо» ×1,5; при критической удаче ×2.
4. Бой длится до поражения стороны или выполнения цели сцены (сбежать, продержаться 3 хода).

## 8. Прокачка и баланс

### 8.1. Решения [РЕШЕНО]

- При росте характеристик бои **не должны становиться сильно легче** — допустимо лишь немного.
- **Враги растут** вместе с группой на **70–120%** — в зависимости от силы врага по сюжету (рейтинга).
- Рост врагов считается от **средней силы группы**.
- **120% — только внутри истории-финала**; между историями враги растут не выше 100%.
- **Пульт ведущего** позволяет добавлять и отнимать характеристики.

### 8.2. Защита от поломок [ПРЕДЛОЖЕНИЕ]

| Риск | Защита |
| --- | --- |
| Снежный ком (повезло → стал сильнее → снова повезло) | «мешок судьбы»; отстающий от среднего на 15+ очков получает +1 к каждой награде |
| Ведущий ошибается или подыгрывает | журнал всех правок на пульте и у игрока («Ведущий: +5 Мудрость за помощь Деметре»), кнопка отмены, лимит ручных правок за историю |
| Разная щедрость историй | норма наград, автоматическая проверка в конструкторе |
| Бесконечный рост | потолок 95, удорожание после 70 |
| Артефакты делают непобедимым | 4 слота, предел суммарного бонуса +15 к одной характеристике |

## 9. Существа: рейтинг силы и скрытые силы

### 9.1. Решения [РЕШЕНО]

- У **каждого существа** свои заданные характеристики.
- Все враги из всех историй распределены по **рейтингу силы от низкого до SSS**. Рейтинг есть у каждого босса и существа, **включая дружественных**: по сюжету они могут стать врагами.
- У всех существ есть **скрытые силы**. Это **сюрприз для всех** — ни ведущий, ни игроки не знают их заранее.

### 9.2. Шкала рейтинга [ПРЕДЛОЖЕНИЕ]

| --- | --- | --- |

| E | стражник Олимпа, сатир | 76% |
| D | кентавр, орк-вожак | 82% |
| C | Минотавр, лестригон | 89% |
| B | Медуза, Эриния | 95% |
| A | Цербер, дракон Ладон | 101% |

| SS | Ехидна, Кронос | 114% |

### 9.3. Карточка существа [ПРЕДЛОЖЕНИЕ]

Единая для всех существ: имя, тип, мир обитания, рейтинг, 6 характеристик, здоровье, способности, слабость (из мифа), поведение, награда, лор, **скрытая сила и условие её раскрытия**, **шкала отношения к игрокам** (−100…+100, для разговорчивых). При отношении ниже −50 друг становится врагом.

Условия раскрытия скрытой силы: здоровье ниже половины, критическая неудача игрока рядом, нарушенная клятва или оскорбление, ночь или определённый мир.

Шаблон: `шаблоны/02_шаблон_существа.md`.

## 10. Артефакты

### 10.1. Решения [РЕШЕНО]

- В игре **большое количество** артефактов; персонаж собирает их по ходу истории.
- Артефакты хранятся у игрока на экране; по нажатию видно, что артефакт даёт.
- Бонусы артефакта складываются с характеристиками персонажа.
- **4 слота.** Новый артефакт брать обязательно, заменив один из старых.
- Плохой (проклятый) артефакт можно положить в **«сумку»**: он действует до конца истории, потом игрок решает, оставить ли его.
- Артефакты достаются **не всем**: кубик решает, кто взаимодействует с персонажем.
- **Свойства зависят от броска:** критическая удача — все положительные стороны; средний бросок — больше в хорошую сторону; критическая неудача — смешанные свойства (что-то добавляет, что-то убавляет).

### 10.2. Механика свойств [ПРЕДЛОЖЕНИЕ]

У каждого артефакта есть полный список свойств (плюсы и минусы). Бросок решает, какие «проснутся». Один и тот же артефакт у разных игроков может оказаться разным.

| Исход | Пример: «Молния Киклопов» |
| --- | --- |
| Критическая удача | +6 Мощь, +3 Мудрость, особый удар раз в бой |
| Хорошо | +5 Мощь, +2 Мудрость |
| Средне | +4 Мощь, −1 Мудрость |
| Плохо | +3 Мощь, −3 Мудрость |
| Критическая неудача | +3 Мощь, −4 Удача, молния может ударить своего |

Шаблон: `шаблоны/03_шаблон_артефакта.md`.

## 12. Истории

### 12.1. Решения [РЕШЕНО]

- **20 шаблонов историй** на старте: хорошие, продуманные, по **10–15 страниц** Word каждая.
- Истории зашиты в игру, **историю выбирает ведущий**.
- Каждая история связана с мирами игры.
- Возможность добавлять **сотни новых историй**.
- **Любая история может идти после любой другой**, несколько историй подряд.
- Истории связаны с богами и существами; игроки участвуют в них за своих персонажей; сюжет «открытый» — его продолжают и закручивают игроки.
- По пути — враги и дружественные персонажи, через которых игроки прокачиваются.

### 12.2. Сага — общее состояние группы [ПРЕДЛОЖЕНИЕ]

Истории не знают друг о друге: они читают Сагу на входе и пишут в неё на выходе.

| Блок Саги | Что хранит |
| --- | --- |
| Герои | характеристики, здоровье, 4 артефакта + сумка, ранения, проклятия, долги |
| Хроника мира | флаги событий («Персефона в плену», «Цербер ушёл») |
| Отношения | отношение каждого существа к каждому игроку |
| Карта | открытые миры, пройденные круги Ада |
| Уровень угрозы | растёт с каждой историей, по нему усиливаются враги |

Пример: `шаблоны/данные/saga.example.json`.

### 12.3. Паспорт истории [ПРЕДЛОЖЕНИЕ]

1. Миры и стартовый уровень угрозы.
2. **Вход** — какие флаги читает (у каждого есть вариант «если нет»).
3. **Выход** — какие флаги ставит при разных финалах.
4. **Крючки** на 2–3 другие истории.
5. **Роли-точки входа** для игроков с запасным вариантом для любого бога.

### 12.4. Связка историй [ПРЕДЛОЖЕНИЕ]

- **Мост** — короткая сцена на 1–2 минуты между историями (вестник Гермеса, вещий сон, разлом, зов бога, погоня).
- Игра предлагает ведущему **3 следующие истории** по крючкам, открытым мирам и уровню угрозы.
- **Вставки** вместо переписывания: важные сцены имеют варианты под флаги Саги.

### 12.5. Правила написания [ПРЕДЛОЖЕНИЕ]

1. Роли, а не имена: точки входа подходят разным богам.
2. Личная зацепка из мифа для каждого бога.
3. Развилки на кубике: и успех, и провал ведут к интересному.
4. Последствия навсегда записываются в Сагу.
5. Крючок на продолжение в конце.
6. Ветки быстро сходятся к узловым сценам — без взрыва ветвлений.

### 12.6. Первые 5 историй (наброски) [ПРЕДЛОЖЕНИЕ]

| История | Завязка | Тайна / крючок |
| --- | --- | --- |
| Вечная зима | Персефона не вернулась ни к Аиду, ни к Деметре; на земле не кончается зима | её поймали пожиратели Внеграничья; на них метка Тёмного мира |
| Второй огонь | цепи Прометея пусты; демоны зажгли «чёрный огонь» | Прометея выпустил кто-то из олимпийцев |
| Яблоко раздора | на совет Олимпа падает яблоко «Сильнейшему» — власть над королевством | проигравшие королевства начинают войну рас |
| Сон царя богов | Зевс уснул и не просыпается; Кронос пробуждается в Тартаре | во сне Зевса — пророчество о падении Олимпа |
| Цербер сорвался с цепи | Цербер исчез, души бегут из Ада | его увели демоны, проверяя путь в Ад |

Три истории указывают на Тёмный мир — основа большой кампании.

## 13. Конструктор историй

**[РЕШЕНО]:** истории создаются через конструктор (схему сцен), чтобы новые истории могли добавлять не программисты.

**Состав минимальной версии [ПРЕДЛОЖЕНИЕ]:**

- сцены-карточки на поле, стрелки между ними;
- в сцене: текст ведущего, участники, проверка (характеристика и сложность);
- 5 исходов броска → награды, флаги, следующая сцена;
- библиотеки: существа, артефакты, миры, мосты — выбор из списка;
- паспорт истории и автопроверка: норма наград, тупики, сцены без выхода;
- тестовый прогон с виртуальными игроками.

Две формы одной истории: **текст для ведущего** (10–15 страниц, как в Word) и **схема сцен** (данные для игры). Пример формата данных: `шаблоны/данные/story.example.json`.

## 14. Техническая архитектура

**[РЕШЕНО]:** всё работает на собственной игровой платформе автора (проект joyrest) на арендованном облачном сервере. Концепт не ресурсоёмкий.

**Принцип [ПРЕДЛОЖЕНИЕ]: сервер считает, устройства рисуют.** Сервер хранит состояние, бросает кубик и рассылает маленькие сообщения об изменениях. Анимации и картинки работают на устройствах.

| Часть | Решение |
| --- | --- |
| Экран игрока | веб-приложение в браузере телефона, вход по QR-коду |
| Пульт ведущего | та же платформа, роль «ведущий» |
| Общий экран | страница в браузере на ТВ |
| Игровой сервер | комнаты, правила, кубик, «мешок судьбы», масштабирование врагов; WebSocket для мгновенных обновлений |
| База | PostgreSQL: Сага, герои, артефакты, журнал бросков и правок |
| Контент | истории, существа, артефакты в формате JSON в базе; новая история = новая запись |
| Медиа | облачное хранилище + CDN |
| Конструктор | раздел админки платформы |
| ИИ-помощник | по желанию, внешний API по кнопке |

**Партия:** ведущий создаёт комнату → QR на общем экране → игроки входят → выбор истории → бросок: сервер выбирает число, пишет в журнал, рассылает всем → награды и флаги в Сагу → карточки обновляются. При обрыве связи экран при возвращении подтягивает актуальное состояние.

**Нагрузка:** для 2–3 партий и 20 человек достаточно одного недорогого сервера (ориентир — 2 ядра, 4 ГБ памяти); подтвердить нагрузочным тестом.
