# «Активные заказы» — логика страницы (источник истины)

Решения владельца 12–13 ноября 2026, макет «JoyRest — «Активные заказы», макет страницы».
Меняется логика страницы — сначала этот файл, потом код (`src/core/orders.ts`, `server/src/events.ts` → `GET /api/orders`,
`src/screens/studio/OrdersTab.tsx`). Тесты — `src/core/orders.test.ts`, `server/src/orders.test.ts`.

## 1. Где и кому

- «Клиенты» → вкладка **«Активные заказы»** (`/studio/clients?tab=orders`), между «База клиентов» и «Мои контакты».
- Видят владелец и менеджер по продажам (`permissions.canManageClients`). У менеджера вкладок раньше не было — теперь две:
  «База клиентов» и «Активные заказы» («Мои контакты» — по-прежнему только владельцу).
- Колонка и итог **«Агентству»** — только владелец (`permissions.canSeeAgencyShare` = `isAdmin`). Менеджеру сервер этих чисел
  не считает, браузер их не рисует.
- Страница **только показывает**. Все действия — в карточке клиента и в «Мероприятиях»: касание строки открывает мероприятие
  (`/studio/calendar?tab=events&event=<id>`), строка «В переговорах» — карточку клиента (`/studio/clients?id=<id>`).
  Поэтому новых путей записи и новых правил «кто что меняет» нет — действуют правила «кто ведёт».

## 2. Откуда данные — один запрос `GET /api/orders`

Один ответ сервера (никаких N запросов из браузера), права — `canManageClients`, ответ `no-store`:

```
{ now, events: OrderEvent[], talks: OrderTalk[] }
```

**`events`** — мероприятия (тот же `select`, что `GET /api/events`, плюс клиент из истории), три набора:

| набор | условие в базе |
|---|---|
| впереди | `cancelled_at is null and ends_at > now()` |
| прошли, не закрыты | `cancelled_at is null and ends_at <= now() and ends_at > now() − 30 дней` и не «закрыто» (ниже) |
| отменены | `cancelled_at is not null` и одно из: ждёт возврата (`refund_at is not null and refund_done_at is null`, сколько угодно долго); отменено за 7 дней (`cancelled_at`); **перенос** — предоплата внесена, возврата нет, клиент по истории «Клиент» и не в архиве, у клиента нет другой брони впереди, отменено за 30 дней (его надо довести до новой даты). Окна считаются от `cancelled_at`: поздние правки отменённого («Забрать себе») их не продлевают |

«Закрыто» (из прошедших не показываем): `held = false` (не состоялось) или `held = true and (rest_paid = 'yes' or price is null or prepaid_at is null) and review <> ''`
(без стоимости или предоплаты остатка нет — такое мероприятие закрывает отзыв).
Каждого набора — не больше 300 (`LIST_MAX`).

К каждому мероприятию — клиент по истории: `client_contacts` с `source = 'event' and ref = e.id` (индекс уникален — клиент один):
`clientId`, `clientStatus`, `clientOwnerName` (кто ведёт клиента, только активный), `nextStep`, `nextAt`, `clientArchived`,
`clientAhead` (у клиента есть другое неотменённое мероприятие впереди). У отменённых — ещё `cancelledAt`. Нет записи истории
(клиент не попал в «Клиенты», старое мероприятие) — эти поля пустые, имя и телефон берутся из самого мероприятия.

**`talks`** — клиенты в переговорах: `status in ('new','work')`, не в архиве, и у них **нет** мероприятия впереди (по той же
истории `source = 'event'`). Поля: `id`, `name`, `status`, `ownerName`, `nextStep`, `nextAt`, `notes` (анкета «Что хочет клиент»),
`newSince`, `tgWaitingSince`, `lastContactAt`, `origin` и **`calc`** — текст последнего обращения с расчётом (сводка истории, кроме
смен статуса, не старше 60 дней, где есть «🧮», «Расчёт JoyRest», «✅» или «Цена:», но **нет** «Расчёта нет» — так заявка с сайта
без расчёта не даёт цену). Из последних 5 таких берётся первый, из которого читается цена (`talkPrice`), нет — просто последний.
Не больше 300, свежие сверху.

Клиент со статусом «Новый»/«В работе», у которого мероприятие впереди уже есть, в «Переговорах» не дублируется — он в «Забронированы».

## 3. Группы (порядок на странице)

1. **Забронированы** — набор «впереди». Внутри — по началу, ближайшие сверху.
2. **В переговорах** — `talks`. Внутри — по дате праздника из анкеты (есть дата — раньше), без даты — в конце, свежие обращения сверху.
3. **Прошли — нужно закрыть** — набор «прошли, не закрыты». Внутри — свежие сверху.
4. **Отменены** — набор «отменены». Сверху — ждущие возврата, дальше — свежие по `cancelledAt`.

Фильтры: «Все», «Требуют внимания», и по группе. Счётчик у фильтра — сколько строк. Ещё: поиск (имя, телефон, ведущий, повод),
«Ведущий» (список из строк), «Кто ведёт клиента» (список из строк), «Порядок»: по дате (как выше), «Сначала срочные» (строки с
подсветкой наверх, внутри — по дате), «По сумме» (больше — выше). Выбор фильтров помнит устройство (`localStorage`
`joyrest.orders.view`, без данных клиентов); ошибка хранилища — просто без памяти.

## 4. Колонки

| колонка | забронированы / прошли / отменены (мероприятие) | в переговорах (клиент) |
|---|---|---|
| Дата и время | `day`, `start–end` по Москве, «через 23 ч» / «идёт сейчас» / «2 дня назад»; отменено — «отменено 11 ноя» (дата `cancelledAt`), с возвратом — «отказ 11 ноя» | дата и время из анкеты (`wishFromText(notes, strict)`), нет — «дата не выбрана»; «ждёт ответа 12 мин» (Новый с таймером или Telegram) |
| Клиент и мероприятие | `clientName` (нет — «Клиент не указан»), `title`, гости, `place` (пусто или «Место уточняется» — жёлтым) | `name`, «Программа: …» из анкеты, гости, источник |
| Статус клиента | `clientStatus` (нет клиента — «нет в «Клиентах»»), под ним «ведёт …» (`clientOwnerName`, иначе `ownerName` мероприятия, иначе «никто не взял») | `status`, «ведёт …» |
| Ведущий | `hostName`; отключён — «⚠ отключён» | «—» |
| Подтвердил | `eventLight` (`src/core/eventLight.ts`) до начала: 🟥 Нужна замена, 🔴 Не подтвердил, 🟡 Ждёт ведущего, 🟢 Принял (время `acceptedAt`); после начала — 🟢 Принял/«—»; отменено — «Отменено» серым | «после брони» |
| Провёл | до начала «ещё впереди»; идёт — 🟠 «Идёт»/🟣 «Сверх плана»; после — 🔵 Проведено, ⚪ «Не отмечено», ⚫ «Не состоялось»; отменено — «Перенос» (подпись «новой даты нет» / «новая дата записана»), только при тех же условиях, что в SQL: клиент «Клиент», не в архиве, предоплата внесена, возврата нет; иначе — «Отменено» | «—» |
| Итого | `price`; нет — «не указана» | `talkPrice(calc)`, нет — `talkPrice(notes)` (менеджер вставил расчёт в заметку), с «≈» и подписью «по расчёту»; расчёт есть, а цены в нём нет («обсудим индивидуально») — «—», «в расчёте нет цены»; расчёта нет — «—», «расчёта нет». `talkPrice` = `priceFromCalc` («✅ … выбран», «Цена:»), иначе строка заявки сайта «Итого: Опытный — N ₽, Новые лица — …» — формат по строке «Ведущий: …», без неё — первый |
| Предоплата | `prepaidAt` → «2 000 ₽ внесена»; нет — «не отмечена» (жёлтым). Отменено: «Вернуть 2 000 ₽» (`refundAt && !refundDoneAt`, красным), «Возвращена» (`refundDoneAt`), «Остаётся» (предоплата была, возврата нет) | «ждём 2 000 ₽» |
| Остаток | `price − 2 000` (только с ценой **и** предоплатой; иначе «—» и подпись «нет стоимости» / «после предоплаты»). После «Проведено»: «получен» / «не получен» / «частично: N ₽» / «не отмечен» (`restPaid`) | — |
| Агентству (только владелец) | `agencyShare(price, guests)` (ниже); отменено — сколько остаётся у агентства: «Остаётся» → 2 000 ₽, иначе (возврат, не вносили) «—» | `≈` по цене из расчёта |
| Следующий шаг | первый подходящий из списка (раздел 6) | «📌 nextStep · дата», нет — «Ответить клиенту» (Новый) / «Договориться о брони» |

Отменённые: сумма зачёркнута, всё серое, «через …» не пишем.

## 5. Деньги

- Предоплата — `PREPAY_RUB` (2 000) из `src/core/prepay.ts`, остаток — `dueOnSite(price, prepaid)`.
- **Доля ведущего** (`hostShare`, решения владельца 16 октября 2026): 55% стоимости, не меньше 5 000 ₽; от 46 гостей —
  20 000 ₽ ровно. **Агентству** = стоимость − доля ведущего, не меньше 0. Формат «Новые лица»/«Первый старт» платформа не знает
  (цена уже со скидкой) — считаем по общему правилу и пишем «≈». 1 000 ₽ менеджеру не вычитаем.
- Итоги сверху (по всем строкам, без фильтров):
  - «Забронировано впереди» — число мероприятий группы 1; ниже «ближайшее — завтра, 19:00».
  - «На сумму» — сумма `price` группы 1 (без цены — не считаются, подпись «N без стоимости»); ниже «на месте — …» (сумма остатков).
  - «Агентству» (только владелец) — сумма долей группы 1; ниже «ведущим — …».
  - «Предоплаты внесены» — 2 000 × число с `prepaidAt` в группе 1; «N из M заказов».
  - «Вернуть предоплату» — 2 000 × число ждущих возврата (группа 4); «N клиент(ов) ждут возврата».
  - «Требуют внимания» — число подсвеченных строк.

## 6. Подсветка («требует внимания») и следующий шаг

Строка красная, если верно хоть одно (порядок = приоритет для «Следующего шага»):

| условие | следующий шаг |
|---|---|
| 🟥 `declinedAt` (ведущий «Не смогу провести») | «Назначить другого ведущего» |
| ведущий отключён (`hostOff`, в колонке «Ведущий» — «Имя · ⚠ отключён») | «Передать мероприятие другому ведущему» |
| 🔴 не подтвердил, до начала < 24 ч | «Позвонить ведущему сегодня ({ведущий})» |
| до начала ≤ 3 дней и место пусто или «Место уточняется» | «Узнать адрес у клиента» |
| до начала ≤ 3 дней и не «Созвонились» (`calledAt`) | «Созвониться с клиентом» |
| прошло, `held = null` | «Узнать у ведущего, как прошло ({ведущий})» |
| проведено, есть остаток (стоимость и предоплата), `restPaid` пусто/no/part | «Остаток: уточнить у ведущего ({ведущий})» |
| проведено, `review` пусто | «Попросить отзыв» (не красная) |
| ждёт возврата | «Вернуть 2 000 ₽ клиенту и отметить» |
| отменено, перенос (см. «Провёл»), новой брони нет | «Согласовать новую дату» |
| мероприятие или переговоры: `nextAt` клиента ≤ сегодня | «📌 {nextStep} · дата» |
| переговоры: «Новый», ждёт ответа > 30 мин (отсчёт `newSince`, у старых карточек без него — `lastContactAt`) или в Telegram > 30 мин | «Ответить клиенту» |

Нет подсветки: «📌 следующий шаг клиента · дата», иначе — «Идёт — отметить «Проведено» после конца» (идёт сейчас) /
«Созвонились — ждём вечера» / «Напоминание придёт за 3 дня» (впереди) / «Новая дата записана» (перенос с новой бронью) /
«Закрыто» (отменено без возврата и без переноса). Предоплата не отмечена у записанного мероприятия впереди — жёлтая подпись, не красная (старые мероприятия до 12 ноября).

## 7. Что меняет строку и как страница обновляется

Строку меняют только действия в других местах: форма мероприятия (цена, ведущий, время, место), «Принял», «Не смогу провести»,
«Проведено», остаток, отзыв, «Созвонились», отмена, «Вернуть предоплату», «Отметить: вернул», статус и «Следующий шаг» клиента,
«Забрать себе». Страница перечитывает `GET /api/orders` раз в 30 с, при возврате на вкладку и после возврата из карточки
(как список «Клиентов»), без мигания: пока идёт запрос, на экране прежние строки; последний ответ помнится в памяти вкладки (для
того же человека), поэтому возврат из карточки сразу показывает строки. Сбой обновления — прежние строки и полоса «Не удалось
обновить — показываем последние данные…», данные не пропадают. Из строки переговоров карточка клиента открывается с `from=orders`,
и «← Активные заказы» возвращает на эту вкладку.

Время («через 23 ч», кружки) — по часам сервера (`now` в ответе + сколько прошло на устройстве), чтобы неверные часы телефона не
перекрашивали строки.

## 8. Телефон и компьютер

- От 1024 px — таблица: шапка «Клиент · Ведущий · Деньги · Что делать», группы блоками со своим цветом и итогом, широкая таблица —
  в прокрутке вбок внутри блока, страница вбок не едет.
- Уже 1024 px — карточки (решение владельца): дата и сумма сверху, клиент, статус и «ведёт», две плашки «Подтвердил»/«Провёл»,
  три числа «Предоплата · Остаток · Агентству», внизу — следующий шаг. Кнопки и строки фильтров ≥ 44 px, фильтры переносятся.

## 9. Узкие места и как закрыты

- **Клиент не связан с мероприятием** (записали без телефона, клиент не попал в «Клиенты») — строка всё равно есть, имя из
  мероприятия, «Статус клиента — —». Клиент «Новый»/«В работе» тогда может оказаться и в «Переговорах» — это правда: в базе он не
  связан; в строке переговоров подсказки нет, связь чинится записью клиента (как сейчас).
- **Один клиент — несколько мероприятий впереди**: каждое — своя строка (заказ = мероприятие).
- **Старые мероприятия без цены и предоплаты** — «не указана» / «не отмечена», суммы итогов их не считают, подписано «N без стоимости».
- **Много строк** — сервер режет каждый набор до 300; «прошли» — только 30 дней, «отменены» — 7 дней (кроме ждущих возврата).
- **Персональные данные** — только тем, кто и так видит «Клиентов»; в журнал сервера — только действие; ничего не уходит в Telegram.
- **Часы телефона** — см. раздел 7.
- **Агентству у менеджера** — не рисуется (браузер считает долю для строк, но плитку, колонку и строку карточки не показывает): экран берёт `permissions.canSeeAgencyShare` (только владелец), проверяет `permissions.test.ts`.
- **Сбой обновления** — прежние строки остаются, сверху «Не удалось обновить — показываем последние данные…»; ответ, пришедший
  позже более свежего, отбрасывается (номер запроса).
- **Пустые поля** — нет гостей или места — в строке без лишних «·»; нет ведущего — «не назначен» (и такой пункт есть в фильтре «Ведущий», последним). Списки фильтров — по алфавиту (`localeCompare`).
- **Пустая страница** — «Активных заказов пока нет» и ссылка «Записать мероприятие» (в планировщик).
