# JoyRest Games — технический паспорт проекта

Этот файл читается в начале каждой сессии Claude Code. Он фиксирует архитектуру и правила.
Любое изменение архитектуры сначала вносится сюда, потом в код.

## 1. Что мы делаем

Интерактивная веб-платформа для ведущих агентства JoyRest (Москва): квизы и игры на
свадьбах, корпоративах, днях рождения. Гости играют со своих телефонов, вопросы
показываются на большом экране, ведущий управляет игрой с пульта.

- Типичное мероприятие: 20–50 гостей. Расчётный максимум: 500 гостей в одной сессии.
- Несколько ведущих работают одновременно, каждый в своих сессиях.
- Язык интерфейса: русский.
- Владелец проекта работает только с телефона: проверка идёт по тестовым ссылкам
  хостинга, а не локально. Всё, что нужно сделать руками, описывай пошагово для
  мобильного браузера.

## 2. Стек

- Vite + React + TypeScript (strict, без `any`).
- Firebase: Authentication (почта/пароль для ведущих, анонимный вход для гостей),
  Firestore (данные и синхронизация в реальном времени). Firestore работает с
  `persistentLocalCache` и `experimentalAutoDetectLongPolling` (медленные мобильные сети).
- Бесплатный тариф Spark: Cloud Functions и Storage не используем.
- Хостинг: Netlify с автопубликацией из GitHub (`netlify.toml`). Каждая ветка получает
  свою тестовую ссылку.
- Тесты: Vitest для логики, эмулятор Firebase для правил безопасности.

### Слой данных и возможный переезд (обязательное правило)

Возможен переезд с Firebase на свой сервер (Node.js + WebSocket на VPS в России). Поэтому:

- Всё, что связано с Firebase (Auth, Firestore, правила), — **только внутри `src/data/`**.
  Экраны, компоненты, механики и `src/core/` не импортируют `firebase/*` и внутренние
  модули слоя данных.
- Экраны и механики работают через интерфейсы `src/data/contracts.ts`: `AuthService`,
  `UsersRepository`, `GamesRepository`, `SessionsRepository`, `ParticipantsRepository`,
  `AnswersRepository`, `ResultsRepository`. Экземпляры (`authService`, `gamesRepo`,
  `sessionsRepo`, …) и типы берутся только из `src/data/index.ts`. При переезде пишется
  новая реализация тех же интерфейсов, остальной код не меняется.
- Логика прав («кто что может») продублирована в `src/data/permissions.ts` обычными
  функциями без Firebase и покрыта тестами (`permissions.test.ts`). Интерфейс решает по ним,
  что показывать; будущий сервер проверяет по ним запросы. `firestore.rules` и
  `permissions.ts` меняются только вместе, вместе с обоими наборами тестов.
- Тест `src/data/boundary.test.ts` проверяет, что вне `src/data/` нет импортов Firebase и
  внутренних модулей слоя данных (единственное исключение — загрузчик SDK в `main.tsx`).

## 3. Роли и экраны

Роли пользователей:
- **admin** — владелец агентства: добавляет и отключает ведущих, ведёт общую библиотеку.
- **host** — ведущий: свои игры, копирование шаблонов, запуск сессий.
- **guest** — гость: анонимный вход по коду сессии, без регистрации.

Регистрация ведущих закрыта: аккаунт создаёт только admin в `/admin` (почта + имя).
Аккаунт создаётся через вторичный экземпляр Firebase Auth (`loadSecondaryAuth`), чтобы
админ не разлогинился; временный пароль показывается один раз и нигде не хранится,
ведущий меняет его в студии. Отключение (`active = false`) блокирует вход в студию и пульт,
создание сессий и игр (так же в правилах). Удалить аккаунт Auth без Cloud Functions нельзя,
поэтому ведущих не удаляем, а отключаем.

Библиотеки игр: общую (`scope: "agency"`) правит только admin, ведущие запускают её игры
как есть или копируют в «Мои игры» (`scope: "personal"`, видит только владелец).

Экраны (маршруты):
- `/studio` — студия: вкладки «Библиотека JoyRest», «Мои игры», «История игр» (`?tab=`).
  `/studio/new` — новая игра, `/studio/games/:id` — игра (автосохранение),
  `/studio/launch/:id` — запуск сессии, `/studio/password` — смена пароля.
- `/admin` — управление ведущими (только admin); при входе — автоочистка старых сессий.
- `/results/:id` — итоги прошедшей игры по ссылке, открываются без входа.
- `/host/:code` — пульт ведущего. Можно открыть на нескольких устройствах сразу.
- `/screen/:code` — экран зала (ноутбук, телевизор, проектор, браузер Smart TV).
- `/play/:code` и `/j` — вход гостя по QR или по коду и телефон игрока.
- `/brand` — служебная витрина фирменного стиля: палитра, шрифты, кнопки, логотипы.

Любое устройство может стать любым экраном, если открыть нужный адрес с кодом сессии.

## 4. Режимы проведения

Ведущий выбирает режим при запуске сессии:
1. **Ноутбук + экран.** Ноутбук показывает экран зала; управление с ноутбука или с
   телефона как пульта (рекомендуемый вариант: ведущий свободно ходит по залу).
2. **Телефон-пульт + отдельный экран.** Экран зала открыт на любом устройстве.
3. **Без экрана.** Только телефон ведущего. Вопросы и варианты показываются прямо на
   телефонах гостей, ведущий читает вслух.

Режим участников:
- **solo** — каждый гость играет сам.
- **teams** — команды; к команде можно подключить несколько телефонов, ответ
  отправляет капитан, остальные видят вопрос.

Вся игровая логика работает с абстракцией «участник» (игрок или команда) и не зависит
от режима.

## 5. Модель данных (Firestore)

```
users/{uid}                 role, name, active, email, createdAt
games/{gameId}              scope: "agency" | "personal", ownerId, title,
                            mechanic, themeId, ageRating: "0+" | "12+" | "18+",
                            content, createdAt, updatedAt (serverTimestamp)
sessions/{sessionId}        code, hostId, gameId, gameTitle, mechanic, gameSnapshot, themeId,
                            playMode: "solo" | "teams",
                            screenMode: "laptop" | "remote" | "none",
                            state { phase: "lobby" | "playing" | "finished",
                                    step, startedAt, revealed },
                            leaderboard { [pid]: { name, kind, score, colorIndex? } },
                            createdAt (serverTimestamp)
sessions/{id}/participants/{pid}   name, kind: "player" | "team", teamId, captainUid,
                                   joinedAt (serverTimestamp)
sessions/{id}/answers/{step_pid}   step, pid, uid, value, submittedAt (serverTimestamp)
results/{sessionId}         hostId, code, gameTitle, mechanic, themeId, playMode,
                            playedAt, participantsCount,
                            board [{ name, score, colorIndex? }] (по убыванию очков),
                            savedAt (serverTimestamp)
```

Уточнения к модели (этап 1):
- `code` — 6 цифр, уникален среди незавершённых сессий. Сессия ищется запросом
  `where code == X` с лимитом 5; из найденных берётся незавершённая.
- Телефон гостя — документ участника с `pid = uid`, поэтому повторный вход не создаёт
  дубль. В режиме teams команда — отдельный документ `kind: "team"` с автоматическим id,
  её создатель — капитан (`captainUid`); телефоны участников команды ссылаются на неё
  через `teamId`. В `leaderboard` попадают только игроки (solo) или только команды (teams).
- Экран зала не слушает участников: пульт ведущего переносит новых участников в
  `leaderboard` с нулём очков, и экран видит их через документ сессии.
- `colorIndex` есть только у команд: пульт выдаёт следующий по порядку цвет команды
  при добавлении в `leaderboard`, и цвет больше не меняется.
- Владелец агентства определяется по UID, зашитому в `firestore.rules` и
  `src/data/config.ts`; его профиль `users/{uid}` создаётся при первом входе. Его нельзя
  отключить, понизить или удалить.

Уточнения к модели (этап 2):
- История игр — коллекция `results`: компактные итоги без ответов и участников. Пульт пишет
  их одной пачкой вместе с `state.phase = "finished"` при завершении игры. `participantsCount` —
  число телефонов гостей. Итоги открываются по ссылке без входа (`allow get: if true`: там
  только названия и очки), списком — только своему ведущему и admin.
- Автоочистка без Cloud Functions: при каждом входе admin в `/admin` удаляются сессии старше
  30 дней (`src/core/retention.ts`) вместе с участниками и ответами — до 100 сессий за вход.
  Если у сессии с участниками ещё нет итогов (игру не завершили), admin сначала сохраняет их.
- Запросы без составных индексов: списки игр, сессий и итогов фильтруются только по
  равенству (или одному диапазону `createdAt`) и сортируются в браузере.

Правила экономии лимитов:
- Гости и экран зала слушают **только документ сессии**. Таблица лидеров хранится в нём.
- Ответы слушает только пульт ведущего.
- При запуске сессии игра копируется в `gameSnapshot`: правка игры в конструкторе не
  ломает идущую сессию.
- Ответ гостя пишется одним документом с детерминированным id `step_pid`, поэтому
  повторное нажатие не создаёт дубль.

Подсчёт очков выполняет пульт ведущего (Cloud Functions на бесплатном тарифе нет).
Правила безопасности разрешают менять `state` и `leaderboard` только владельцу сессии.
Удалять сессии может владелец и admin (автоочистка).

Честность вопросов на скорость: время ответа = `submittedAt − state.startedAt`, оба
значения ставит сервер (`serverTimestamp`). Часам телефонов не доверяем.

## 6. Механики как модули

Каждая механика — отдельная папка `src/mechanics/<id>/` с единым интерфейсом:

```ts
interface Mechanic<Content, Answer> {
  id: string;
  title: string;
  supports: { solo: boolean; teams: boolean; noScreen: boolean };
  Editor: Component;        // конструктор
  ScreenView: Component;    // экран зала
  PlayerView: Component;    // телефон гостя
  HostControls: Component;  // пульт
  steps(content): Step[];   // последовательность шагов игры
  score(step, answers): ScoreDelta[];
  validate(content): ValidationError[];
}
```

Новая механика подключается регистрацией в `src/mechanics/registry.ts` и не требует
изменений в ядре. Ядро ничего не знает о конкретных играх.

Очередь механик:
1. Квиз: варианты ответа, открытый ответ, на скорость, вопрос с картинкой и аудио.
2. «Угадай мелодию» и музыкальное лото.
3. Тайные роли: Мафия, Бункер, Шпион.
4. Игровые поля: Just Dance Battle, ходилки «Алкогольные / Сладкие приключения».
5. Голосования: Битва тостов, Замри.

## 7. Музыка и медиа

- Основной режим: аудиофайлы выбираются с устройства ведущего и хранятся локально
  (IndexedDB) на том устройстве, где открыт экран зала. На сервер не загружаются.
- В игре хранится только ссылка на трек: имя файла, начало фрагмента, длительность.
- Если файла нет на устройстве, экран зала показывает понятное сообщение и предлагает
  выбрать файл заново.
- Запасной режим «свой плеер»: платформа показывает только кнопки и считает очки.
- Звук играет только на экране зала, никогда на телефонах гостей.

## 8. Темы оформления

Тема — это данные, а не код: палитра, шрифты, фон, звуки, анимации.

```
themes/<id>.ts   id, title, kind: "brand" | "seasonal" | "occasion",
                 tokens { colors, fonts, radius, background }, sounds, ageRating
```

- Базовая тема — фирменный стиль JoyRest.
- Сезонные: Новый год, 23 февраля / 8 марта, лето, Хэллоуин и т.д.
- Тематические: свадьба, корпоратив, детский праздник, 18+.
- Компоненты используют только CSS-переменные из токенов, никаких цветов «в коде».
- Возрастные ограничения: контент и темы 18+ не предлагаются в детских играх.

### Фирменный стиль JoyRest

Слоган — «Радость без хлопот». Палитра — `src/themes/brand.ts`, темы — `src/themes/joyrest.ts`,
витрина — маршрут `/brand`.

Темы `brand`:
- `joyrest` — вечерняя, базовая. Фон #221E1B, карточки #2A2622, разделители тёплые
  полупрозрачные (золото с прозрачностью 18%), текст #FBF6F1, второстепенный #B5ABA2.
- `joyrest-day` — дневная. Фон #FBF6F1, карточки белые, текст #362E29, второстепенный #7A6E66.
- Ведущий выбирает тему при создании сессии; пульт, экран зала и телефоны гостей
  показывают тему сессии, студия — всегда вечернюю.

Цвета:
- Главный акцент — пыльная роза #C49E96: основные кнопки. Текст на них тёмный #221E1B
  (светлый текст на розе даёт контраст 2.25 — нельзя). Рядом в палитре: коралл #E3AA9C,
  винный #D2A0AC.
- Второй акцент — градиент #E3C68C → #A3C2AA: только акценты (крупный код игры в вечерней
  теме, бейджи, полосы). Для обычных кнопок градиент не используем.
- Цвета команд (пастель, текст на них тёмный): #E3AA9C, #E3C68C, #A3C2AA, #D2A0AC, #B3AADD.
- Контраст проверяет тест `src/themes/contrast.test.ts` (WCAG AA: текст ≥ 4.5,
  рамки и фокус ≥ 3) для каждой темы. Новую тему без зелёного теста не добавляем.

Шрифты — свои файлы в `public/fonts/` (woff2, только latin + cyrillic, `font-display: swap`,
описание в `src/fonts.css`, лицензия OFL). Google Fonts не подключаем. В `index.html`
предзагружены Jost 400 (cyrillic, latin) и Cormorant Garamond 700 (cyrillic); файлы
кэшируются на год, поэтому при замене файла меняйте его имя.
- Cormorant Garamond 600/700 — заголовки и код игры.
- Jost 400/500/600 — текст, подписи, кнопки.

### Правила интерфейса (для всех новых экранов)

Кнопки — ровно три вида на всю платформу (`src/styles.css`), других не придумываем:
- **основная** `.btn` — заливка #C49E96, текст #221E1B, жирный (Jost 600). Одна главная
  кнопка на блок: «Открыть экран зала», «Начать игру», «Создать сессию».
- **вторичная** `.btn--secondary` — прозрачная, контур 1.5px #E3C68C, текст #FBF6F1
  (в дневной теме контур #9A7444 и тёмный текст — цвета берутся из токенов `highlight`
  и `text`). «Скопировать ссылку», «В студию», «Выйти».
- **тихая** `.btn--quiet` — только текст, без рамки: пункты меню и третьестепенные действия.
- Высота любой кнопки и поля ввода — не меньше 52px (сейчас 56px, `--control-height`).
  На телефоне кнопки блока стоят столбиком во всю ширину (`.actions`), без переносов в ряд.

Выбор вариантов — карточки `.choice` со своей радиокнопкой (никаких системных кружков):
- невыбранная — тонкое кольцо 2px цвета `control` (#B5ABA2), карточка с обычной рамкой;
- выбранная — кольцо и точка цвета `controlChecked` (#C49E96), карточка с обводкой
  `highlight` (#E3C68C). В дневной теме — #7A6E66, #8A5148 и #9A7444 (иначе контраст < 3).
- Внутри: `.choice__title` (жирный) и `.choice__hint` (второстепенный).

Шапка — компонент `TopBar`: монограмма, «JoyRest Games» одной строкой, название экрана.
Действия передаются списком `actions`: на телефоне — одна кнопка-меню ☰, от 720px —
вторичные кнопки в ряд.

QR-код — только компонент `QrCode` (`src/brand/qrSvg.ts`): кремовая скруглённая плашка
#FBF6F1, модули #221E1B, тихая зона 4 модуля со всех сторон, уровень коррекции H,
монограмма J✦R в центре на кремовой подложке не больше 20% ширины кода. Цвета не зависят
от темы. Тест `src/brand/qrSvg.test.ts` растеризует код и распознаёт его (jsQR) —
после любых правок QR он должен быть зелёным.

Код игры — `.big-code`: без переносов, Cormorant 700, градиент темы; контраст обоих
концов градиента с фоном и с карточкой ≥ 4.5 проверяет тест контраста.

Сетка и поля:
- отступы кратны 8px (8, 16, 24, 32); внутренний отступ карточек 24px, промежутки 16px;
- поля страницы на телефоне 20px, учитываются `safe-area` сверху, снизу и по бокам;
- снизу у страницы запас 88px (`--bottom-clearance`): плавающая панель Netlify на тестовых
  ссылках и уведомления не перекрывают контент;
- заголовки с `text-wrap: balance`, длинные строки (адрес, код) — в одну строку с обрезкой.

Вкладки — компонент `Tabs`: тихие кнопки, у выбранной полоса градиента снизу, стрелки
переключают. Дополнительные действия карточки — кнопка «⋯» (`ActionMenu`, тот же список,
что меню ☰ в шапке). Необратимые действия («Удалить игру», «Отключить») — только через
`ConfirmDialog`. Подробности карточки (механика, тема, число вопросов, дата) — плашки `.meta`.

Загрузка: вместо текста «Загружаем…» — каркас экрана (`src/components/Skeleton.tsx`)
через `Pending`; если загрузка дольше 8 секунд — сообщение и кнопка «Повторить».
Уведомления о действиях — `Toast` («Ссылка скопирована»).

Скорость: Firebase грузится динамически (`src/data/firebase.ts`) через обёртки
`src/data/sdk/*.ts` с именованным реэкспортом — новую функцию SDK добавляйте туда,
иначе пропадёт tree-shaking. Экраны — отдельные чанки (`lazy` в `App.tsx`); главная и
`/j` не грузят Firebase.

Логотип — готовые файлы в `public/brand/` (не перерисовывать):
- `joyrest-logo.svg` — полный логотип: монограмма «J✦R», JOYREST, EVENTS & EXPERIENCES;
- `joyrest-monogram.svg` — монограмма;
- `joyrest-emblem.svg` — эмблема с аркой для заставки;
- `favicon.svg` — иконка сайта.

Логотипы закрашены `currentColor` и встраиваются в страницу компонентом
`src/components/Logo.tsx` (импорт `?inline-svg`, метаданные вырезаются при сборке). Цвет —
`--color-logo` из темы, id внутри clipPath делаются уникальными для каждого экземпляра.

Размещение: эмблема крупно на заставке экрана зала, пока гости подключаются; монограмма
в углу экрана зала во время игры и после неё; полный логотип над формой входа гостя;
монограмма в шапке пульта и студии; монограмма в центре QR-кода.

## 9. Надёжность — обязательные требования

- Гость, у которого погас экран или пропал интернет, возвращается в игру автоматически
  и видит текущий шаг.
- Если ведущий закрыл вкладку, игра продолжается с того же места после открытия пульта.
- Слабый интернет на площадке — норма: на телефон гостя передаём минимум данных,
  тяжёлые медиа только на экране зала.
- Нагрузочный симулятор `scripts/simulate.ts`: запускает N виртуальных гостей
  (до 500) против тестовой сессии. Прогонять перед каждым релизом механики.
- Конструктор сохраняет изменения автоматически, ни одна правка не теряется
  (`src/components/useAutosave.ts`: пачка правок через 0,7 с, повтор после ошибки,
  досылка при сворачивании вкладки; офлайн-записи держит локальный кэш Firestore).

## 10. Правила разработки

- Маленькие задачи, понятные коммиты на русском языке.
- Каждая механика покрыта тестами логики `steps` и `score`.
- Правила безопасности Firestore лежат в `firestore.rules` и покрыты тестами.
  После изменения правил напиши владельцу пошагово, как вставить их в консоль Firebase.
- Секреты в репозиторий не кладём. Конфигурация веб-приложения Firebase не секретна;
  ключи сервисного аккаунта запрещены.
- Интерфейс: сначала мобильная версия для гостя, крупные кнопки, видимый фокус,
  уважение к настройке «уменьшить движение».
- Тексты интерфейса простые и конкретные: кнопка называет действие («Начать игру»,
  «Показать ответ»).
- После каждой завершённой задачи кратко сообщай, что проверить по тестовой ссылке.
