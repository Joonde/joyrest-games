## Что хранить у себя (не на сервере)

Без этого при потере сервера восстановиться нельзя. Храните в менеджере паролей или
в защищённой заметке, не в чатах.

| Что | Откуда | Зачем |
|---|---|---|
| Ключ Termius (Keychain) | создаёте сами в Termius | вход на сервер |
| Пароль root в панели Beget | панель Beget | аварийная консоль (VNC), если вход по ключу сломался |
| Токен GitHub `read:packages` и **дата его окончания** | GitHub → Developer settings | сервер скачивает образы |
| Пароль резервных копий, адрес и имя бакета, ключи Beget S3 | пароль покажет `sudo joyrest backup-setup` один раз, остальное — панель Beget | без пароля копии в S3 не расшифровать никому |
| Почта и пароль admin JoyRest | покажет настройка (PR 3) один раз | вход в студию |

## Первичная настройка сервера

### 1. Ключ для входа (Termius)

1. Termius → **Keychain** → **+** → **Generate Key**.
2. Тип **ED25519**, имя `joyrest` → **Save**.
3. Откройте ключ → **Export** / **Copy public key**. Строка начинается с `ssh-ed25519`.
   Её спросит установка.

### 2. Токен GitHub для скачивания образов

1. github.com в браузере → аватар → **Settings** → **Developer settings** →
   **Personal access tokens** → **Tokens (classic)** → **Generate new token (classic)**.
2. Note: `joyrest-server-pull`. Expiration: **1 год** (запишите дату).
3. Отметьте **только** `read:packages` → **Generate token** → скопируйте токен.

### 3. Проверка связи

Termius → новый хост: адрес `217.114.13.92`, пользователь `root`, пароль из Beget.
Вставьте блок из сообщения Claude (файл `deploy/setup/check.sh`) и запустите:

```
bash check.sh
```

Скрипт ничего не меняет. Пришлите скриншот итоговой таблицы.

### 4. Установка

Вставьте блок с `install.sh` из сообщения Claude, затем:

```
bash install.sh
```

Скрипт спросит:
- почту администратора (Enter — `student.maik@gmail.com`);
- имя вашего пользователя (Enter — `joy`);
- публичный ключ из шага 1;
- токен из шага 2 (при вставке символы не видны, это нормально).

В конце скрипт **один раз** покажет два секрета: `DEPLOY_SSH_KEY` и `DEPLOY_KNOWN_HOSTS`.
Каждый — одна длинная строка: двойное касание выделяет её целиком.

### 5. Секреты в GitHub

github.com → репозиторий `joyrest-games` → **Settings** → **Secrets and variables** →
**Actions** → **New repository secret**. Создайте:
- `DEPLOY_SSH_KEY` — первая строка из шага 4;
- `DEPLOY_KNOWN_HOSTS` — вторая строка из шага 4.

### 6. Проверка входа по ключу

В Termius создайте **новый** хост: адрес `217.114.13.92`, пользователь `joy`, ключ `joyrest`
(без пароля). Подключитесь и выполните:

```
joyrest status
```

### 7. Перезагрузка и проверка, что всё поднялось само

Установка обновила систему и, скорее всего, ядро. Новое ядро начинает работать только после
перезагрузки, а заодно проверим главное: после перезапуска сервера сайт встаёт без вашего участия.

1. Под `joy` проверьте, нужна ли перезагрузка:

```
[ -f /var/run/reboot-required ] && echo "Нужна перезагрузка" || echo "Перезагрузка не нужна"
```

2. Перезагрузите (Termius отключится — это нормально):

```
sudo reboot
```

3. Подождите 2 минуты, подключитесь снова под `joy` и выполните:

```
uname -r && joyrest status
```

Все три сервиса должны быть `Up`, у `app-prod` и `postgres` — `(healthy)`, в строке
«Здоровье» — `"ok":true`. Если `app-prod` ещё `starting`, подождите минуту и повторите.

4. В браузере телефона откройте https://games.joy-rest.ru/health — `"ok":true`,
и https://joy-rest.ru — заглушка «Радость без хлопот».

Если через 5 минут сайт не поднялся: `sudo joyrest up`, затем `joyrest logs 100` —
скриншот пришлите Claude.

### 8. Выкладка из GitHub

Порядок важен: сначала обновить сервер, потом настроить Telegram, и только в конце включить
выкладку переменной `DEPLOY_ENABLED`.

**8.1. Обновить сервер** (только для сервера, установленного до PR 2; один раз, под `joy`).
Блок сначала скачивает свежий образ `main` — иначе взялся бы старый образ с сервера и
скопировал бы старую команду `joyrest`.

```
sudo docker pull -q ghcr.io/joonde/joyrest-app:main \
  && cid=$(sudo docker create ghcr.io/joonde/joyrest-app:main) \
  && sudo docker cp "$cid":/app/deploy/bin/joyrest /usr/local/bin/joyrest \
  && sudo docker rm "$cid" >/dev/null \
  && sudo joyrest activate main
```

В конце должно быть «[prod] … выложена». Проверка:

```
joyrest status && systemctl list-timers joyrest-update.timer --no-pager
```

В `joyrest status` — сервисы `app-prod` и `app-test` (healthy) и строка «Выкладка prod: … ok».
Таймер `joyrest-update` включён, но пока `DEPLOY_ENABLED` не задана, GitHub не ставит тег
`release`, и таймеру нечего забирать.

**8.2. Бот Telegram для сообщений о выкладке:**
1. Telegram → **@BotFather** → `/newbot` → название `JoyRest Монитор` → имя на `_bot`
   (например `joyrest_monitor_bot`). BotFather пришлёт токен вида `123456789:AA…`.
2. Откройте своего бота и нажмите **Старт**, напишите ему любое слово.
3. В браузере телефона откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
   (вместо `<ТОКЕН>` — токен целиком). Найдите `"chat":{"id":` — число после него
   и есть ID чата.

**8.3. Секреты в GitHub** (Settings → Secrets and variables → Actions → вкладка **Secrets** →
New repository secret): `TELEGRAM_BOT_TOKEN` (токен), `TELEGRAM_CHAT_ID` (число).
`DEPLOY_SSH_KEY` и `DEPLOY_KNOWN_HOSTS` уже есть (шаг 5).

**8.4. Включить выкладку — последним:** вкладка **Variables** → New repository variable:
`DEPLOY_ENABLED` = `true`. Пока её нет, GitHub только собирает образы: не выкладывает по SSH
и не ставит теги `release` / `test-release`. Выключить выкладку — удалить переменную или
поставить `false`.

**Проверка:** любой новый коммит в `main` → через 3–5 минут в Telegram
«✅ Выложено на games.joy-rest.ru … (по SSH)», `joyrest status` показывает ту же версию.

### 9. Запрет входа root и паролей

Только после того, как вход `joy` по ключу работает и выкладка из GitHub проверена
(сообщение «✅ Выложено … (по SSH)»). После этого шага на сервер по SSH можно войти только
пользователем `joy` по ключу из Termius; аварийный вход — консоль VNC в панели Beget (root с
паролем из панели, она от SSH не зависит).

1. Войдите в Termius как `joy` (по ключу). Вставьте блок со скриптом из сообщения Claude
   (файл `deploy/setup/lock-ssh.sh`) — он сохранит его в `~/lock-ssh.sh`.
2. Сначала посмотрите, что будет сделано (ничего не меняет):

```
sudo bash ~/lock-ssh.sh --check
```

   Должно быть две ✅ (ключ `joy`, ключ выкладки `deploy`) и блок «Будет записано».
3. Примените:

```
sudo bash ~/lock-ssh.sh
```

   В конце — «✅ Готово… Итог: permitrootlogin no; passwordauthentication no; …». Если
   скрипт пишет «❌ … возвращаю прежние настройки SSH», ничего не сломано: вход как раньше,
   пришлите вывод Claude.
4. **Не закрывая это окно**, откройте в Termius новое подключение под `joy` — должно войти
   без пароля. Затем попробуйте подключение под `root` — должен быть отказ
   («Permission denied»).
5. Если новое подключение под `joy` не входит — в старом окне верните прежние настройки:

```
sudo rm /etc/ssh/sshd_config.d/10-joyrest.conf && sudo systemctl reload ssh
```

   и пришлите Claude вывод. Если окно уже закрыто — панель Beget → VPS → **Консоль (VNC)**,
   вход `root` с паролем из панели, та же команда без `sudo`.

## Каждый день

Все команды — под пользователем `joy`. `joyrest` сам берёт права администратора через
`sudo` (у `joy` sudo без пароля), поэтому `sudo` перед ним можно не писать.

Если сервер установлен до PR 2 и шаг 8 ещё не выполнен, старая версия команды так не умеет:
пишите `sudo joyrest status` (иначе будет ошибка `permission denied` на `secrets.env`).

### Всё ли в порядке

```
joyrest status
```

Покажет версию, состояние контейнеров (`healthy` — хорошо), диск, память и сколько памяти
занимает каждый контейнер. Из браузера: https://games.joy-rest.ru/health — `"ok":true`.

### Логи

```
joyrest logs app-prod 100
```

Вместо `app-prod` можно указать `app-test` (тестовое окружение), `caddy` (HTTPS и
сертификаты) или `postgres` (база).
Без названия — логи всех сервисов. Логи хранятся до 30 МБ на контейнер, старые удаляются сами.

### Перезапуск

```
sudo joyrest restart app-prod
```

Без названия перезапускается всё. Гости и экран зала переподключатся сами.

### Обновления системы и перезагрузка

Обновления безопасности ставятся сами каждую ночь, но сервер сам **не** перезагружается
(чтобы не оборвать праздник). Раз в неделю проверьте:

```
[ -f /var/run/reboot-required ] && echo "Нужна перезагрузка" || echo "Перезагрузка не нужна"
```

Если нужна — в день без мероприятий: `sudo reboot`, через 2 минуты `joyrest status`
(как в шаге 7 настройки). Сайт будет недоступен около минуты.

## Выкладка и откат

### Как это работает

- Коммит в `main` → GitHub Actions: тесты → образ → выкладка на **games.joy-rest.ru**.
- Коммит в ветку `claude/…` → то же на **test.games.joy-rest.ru** (тестовое окружение,
  своя база; основную версию не трогает).
- Сайт агентства собирается в тот же образ: `main` → **joy-rest.ru** (пока выключен, там
  заглушка), ветки `claude/…` → **test.joy-rest.ru** (по паролю). Выкладка, откат и сообщения
  в Telegram — общие с платформой. Выкладка сайт **не включает**.
- Caddyfile и команды `joyrest` берутся из основной версии: новое в них появляется на сервере
  только после слияния в `main`.
- Выкладка на сервере: дамп базы → миграции → переключение → проверка `/health`.
  Если новая версия не ответила за 2 минуты — **сервер сам возвращает прошлую**.
- Два пути доставки: GitHub подключается по SSH; если SSH не прошёл, сервер сам
  забирает релиз из GHCR (проверяет каждые 2 минуты). Итог в Telegram:
  «✅ Выложено … (по SSH)» или «(сервер забрал сам)», при ошибке «❌ Не выложено» и причина.
- **Во время игры основную версию не выкладываем.** Если в какой-то сессии была активность
  за последние 30 минут, выкладка ждёт и сама пройдёт после игры (сообщение
  «❌ Не выложено … blocked: идёт игра» — это не авария). Забытая сессия без активности
  выкладку не держит. Если сервер не смог проверить, идёт ли игра (база не ответила),
  выкладка тоже ждёт («blocked: не удалось проверить») и повторяется каждые 2 минуты.
  GitHub сам `force` не отправляет никогда — только вы вручную.

### Посмотреть состояние

```
joyrest status
```

Строки «Выкладка prod» и «Выкладка test»: `ok` — выложено, `blocked` — ждёт конца игры,
`failed` — ошибка (версия не переключилась или вернулась прошлая), `running` — идёт.
Журнал выкладок: `sudo tail -n 30 /srv/joyrest/deploy/deploy.log`.

### Вернуть прошлую версию

```
sudo joyrest rollback
```

Для тестового окружения — `sudo joyrest rollback test`. Откат идёт сразу, даже во время
игры (это аварийная кнопка). Дамп базы перед каждой выкладкой лежит в
`/srv/joyrest/backups/predeploy/` (последние 5).

### Выложить конкретную версию вручную

```
sudo joyrest deploy <коммит>
```

`<коммит>` — 40 символов из GitHub (страница коммита → значок копирования). Во время игры
выкладка не пойдёт; если всё-таки нужно — добавьте `force` в конце. Из браузера то же:
GitHub → **Actions** → **Сборка** → **Run workflow** → ветка `main`, галочка
«Выложить … даже если идёт игра».

## Сайт агентства joy-rest.ru

Пока у владельца нет ИП, сайт **выключен**: на joy-rest.ru заглушка «скоро», заявки не
принимаются. Сам он не включится — ни после слияния, ни после выкладки, ни после
перезагрузки сервера. Посмотреть: `joyrest site`.

### Пароль для test.joy-rest.ru

Тестовый адрес показывает сайт всегда, но только по логину и паролю. Пока пароль не задан,
туда не пускает никого.

```
sudo joyrest site-password
```

Команда спросит логин (Enter — `joyrest`) и пароль дважды (не короче 12 символов, при
вводе не виден). На сервере остаётся только хэш, сам пароль — нигде; сохраните его в
менеджере паролей. Забыли — просто задайте новый той же командой. Сайт заработает сразу,
без перезапуска.

### Включить сайт на joy-rest.ru

Когда юридические вопросы решены (ИП, политика с ФИО и ИНН), сначала настройте бота (ниже),
потом:

```
sudo joyrest site on
```

Выключить обратно — `sudo joyrest site off` (заглушка, заявки не принимаются, индексация
тоже выключается). Во время игры команда откажется — повторите после игры или добавьте `force`.

### Бот для заявок

Заявки с сайта (вопрос, отзыв, заявка) сервер пересылает в Telegram. Токен бота хранится
**только на сервере** в `/srv/joyrest/secrets.env` — не в GitHub, не в образе, не в чатах.
Пока бот не настроен, сайт работает, а формы отвечают «Форма временно не работает» со ссылкой
на t.me/JoyRest. Бота можно настроить заранее, пока сайт выключен, и проверить формы на
test.joy-rest.ru.

1. В Telegram: @BotFather → `/newbot` (или `/mybots` → ваш бот) → скопируйте **API Token**.
2. Добавьте бота в группу, куда должны приходить заявки (или напишите боту `/start` в личке).
3. Узнайте id чата: добавьте в группу @RawDataBot (или перешлите ему сообщение из группы) —
   число вида `-1001234567890`; потом @RawDataBot из группы удалите.
4. В Termius:

```
sudo joyrest lead-bot
```

Команда спросит токен (при вставке символы не видны — это нормально) и id чата, проверит
бота, отправит пробное сообщение, сохранит и перезапустит приложение (несколько секунд).
Во время игры она откажется — повторите после игры или добавьте `force`.
С тестового адреса test.joy-rest.ru заявки приходят в тот же чат с пометкой «🧪 ТЕСТ».

Если токен попал куда-то кроме сервера (чат, скриншот, GitHub): @BotFather → `/mybots` →
бот → API Token → **Revoke**, затем снова `sudo joyrest lead-bot` с новым токеном.

### Поисковики

Сайт закрыт от поисковиков (robots.txt `Disallow: /` и заголовок `X-Robots-Tag: noindex`).
Открыть можно только включённый сайт (`sudo joyrest site on`), когда готовы юридические
вопросы (политика, ФИО, ИНН):

```
sudo joyrest site-indexing on
```

Закрыть снова — `sudo joyrest site-indexing off`, посмотреть — `joyrest site-indexing`.
Проверка в браузере: https://joy-rest.ru/robots.txt. Тестовый адрес закрыт всегда.

## Резервные копии

### Как это работает

- Каждую ночь в 04:40 сервер делает копию основной базы: файл на диске сервера (3 последних)
  и зашифрованная копия в хранилище S3 Beget (в России). Хранятся **7 ежедневных, 4 еженедельных
  и 3 ежемесячных** копии — данные, удалённые из базы, остаются в копиях до 3 месяцев.
- Раз в неделю сервер удаляет старые копии и проверяет целостность части данных, раз в месяц —
  разворачивает последнюю копию во временную базу и проверяет, что она восстанавливается.
  Если в это время идёт игра (активность за 30 минут), это переносится на следующую ночь.
- Копия не получилась → сообщение в Telegram «⚠️ Резервная копия не сделана: причина».
  Удачные копии — без сообщений, раз в неделю короткий итог.
- Копии зашифрованы паролем. **Без пароля их не расшифровать никому** — ни вам, ни Claude,
  ни Beget. Пароль на сервере есть, но если сервер погибнет, останется только ваша копия.

### 1. Бакет и ключ в панели Beget (с телефона)

Названия пунктов в панели могут немного отличаться — ищите по смыслу.

1. Откройте https://cp.beget.com → войдите → раздел **Облако** → **S3-хранилище**.
2. **Создать** (новый бакет): название `joyrest-backups`, регион `ru1`, доступ **приватный**
   (не публичный). Объём — минимальный: копии сейчас занимают килобайты.
3. Откройте созданный бакет. Если есть переключатель **FTP/SFTP** — выключите: для копий он не
   нужен, а это лишний вход в хранилище.
4. В разделе доступа бакета найдите и сохраните в менеджер паролей:
   **адрес (endpoint)** — обычно `https://s3.ru1.storage.beget.cloud`, **имя бакета** (может
   отличаться от названия, например с префиксом), **Access key**, **Secret key**.

Версионирование и запрет удаления (object lock): в документации и настройках бакета Beget
их нет. Поэтому тот, кто получит доступ к серверу, сможет удалить и копии в S3. Если увидите
в панели бакета «Версионирование» или «Блокировку объектов» — напишите Claude, добавим.

### 2. Служебный бот (сообщения о копиях)

Тот же бот **JoyRest_Сервер**, который пишет «✅ Выложено». Токен: @BotFather → `/mybots` →
бот → **API Token**. Chat id — тот же, что `TELEGRAM_CHAT_ID` в GitHub (GitHub → репозиторий →
Settings → Secrets and variables → Actions; значение там не видно — возьмите из своих записей
или у @userinfobot / @getidsbot в нужном чате).

```
sudo joyrest notify-bot
```

Токен вводится скрыто, в чат придёт пробное сообщение. Приложение не перезапускается.

### 3. Подключение хранилища

```
sudo joyrest backup-setup
```

Спросит адрес, имя бакета и ключи (secret key — скрыто), затем покажет **пароль копий**
отдельной строкой:

1. Долгое нажатие на строку → **Copy** → вставьте в менеджер паролей рядом с ключами S3.
2. Команда попросит ввести **последние 4 символа** пароля — так видно, что он сохранён.
3. После этого пароль убирается с экрана, сервер делает первую копию.

Если сервер переустановлен и копии в бакете уже есть, команда это увидит и попросит
сохранённый пароль.

### Проверить

```
joyrest status
```

Строка «Резервная копия: последняя 07.10 04:41 (…) ✅». ⚠️ — копии нет больше 36 часов или
хранилище не настроено. Список копий и итоги проверок:

```
sudo joyrest backups
```

Сделать копию сейчас: `sudo joyrest backup`.

### Восстановить

Сначала — в тестовую базу (основную не трогает), проверьте на https://test.games.joy-rest.ru:

```
sudo joyrest restore latest test
```

Вместо `latest` — ID копии из `sudo joyrest backups` (первая колонка).

Основная база (только когда точно нужно, лучше в день без мероприятий):

```
sudo joyrest restore latest prod
```

Команда спросит подтверждение (напишите `восстановить`), сохранит дамп текущей базы,
остановит приложение примерно на минуту, подставит копию и запустит приложение. Прежняя база
остаётся на сервере как `joyrest_prod_before_restore` до следующего восстановления. Во время
игры команда откажет; если игра «зависла», а восстановить нужно — добавьте `force` в конце.

### Сервер погиб: всё с нуля

1. Новый сервер — «Первичная настройка сервера» (шаги 1–8).
2. `sudo joyrest backup-setup` — те же адрес, бакет, ключи; команда попросит сохранённый пароль.
3. `sudo joyrest restore latest prod force` — база.
4. `sudo joyrest restore-settings`, затем `sudo joyrest up` — настройки сайта и пароль
   test.joy-rest.ru. Ботов (`sudo joyrest lead-bot`, `sudo joyrest notify-bot`) задайте заново:
   токены в копии не попадают.

## Если что-то сломалось

- **Сайт не открывается.** `joyrest status`. Если контейнер не `Up` —
  `sudo joyrest restart`, затем `joyrest logs <сервис> 200`. Скриншот пришлите Claude.
- **Ошибка сертификата.** `joyrest logs caddy 200`. Проверьте, что в DNS Beget домены
  указывают на `217.114.13.92`.
- **Не пускает по ключу.** Панель Beget → VPS → **Консоль (VNC)** → вход `root` с паролем
  из панели. Запрет входа root касается только SSH, консоль Beget работает всегда.
- **Диск заполнен.** `joyrest status` (строка «Диск»), затем `sudo docker image prune -a`:
  команда удаляет образы, которые сейчас не используются.

- **Выкладка не проходит («❌ Не выложено»).** Прочитайте причину в сообщении, затем
  `sudo tail -n 50 /srv/joyrest/deploy/deploy.log` — скриншот пришлите Claude. Сайт при
  этом работает на прошлой версии.

- **«⚠️ Резервная копия не сделана».** `sudo joyrest backups` и
  `sudo grep backup /srv/joyrest/deploy/deploy.log | tail -n 20` — скриншот пришлите Claude.
  Частые причины: истёк или удалён ключ S3 в панели Beget, закончились деньги на балансе Beget.
